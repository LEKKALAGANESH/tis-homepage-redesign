# Delivery & Release Checklist

## 1. Repository

- [ ] Repository is public.
- [ ] Default branch contains the final implementation.
- [ ] README explains project purpose.
- [ ] README explains setup.
- [ ] README identifies actual technology choices.
- [ ] README contains the live deployment URL.
- [ ] README contains the repository URL.

## 2. Build

- [ ] Dependencies install successfully.
- [ ] Development server starts.
- [ ] Production build succeeds.
- [ ] No known build errors.
- [ ] No known runtime errors.

## 3. Feature verification

- [ ] At least two assessment standout features are implemented.
- [ ] Each selected feature has been manually verified.
- [ ] Features work at desktop sizes.
- [ ] Features do not break touch/mobile behavior.

## 4. Responsive verification

- [ ] 375px
- [ ] 768px
- [ ] 1280px+
- [ ] No horizontal overflow.
- [ ] No clipped content.
- [ ] No broken navigation.
- [ ] CTAs remain usable.

## 5. Accessibility verification

- [ ] Semantic landmarks.
- [ ] Keyboard navigation.
- [ ] Visible focus.
- [ ] Accessible contrast.
- [ ] Reduced-motion behavior.
- [ ] Touch-friendly controls.

## 6. Code hygiene

- [ ] No unused dependencies.
- [ ] No dead code.
- [ ] No forgotten console logs.
- [ ] No accidental secrets.
- [ ] Imports are clean.
- [ ] Components have understandable boundaries.

## 7. Documentation

- [ ] README complete.
- [ ] PRD complete.
- [ ] Architecture complete.
- [ ] Design complete.
- [ ] Tasks complete.
- [ ] Process documented.
- [ ] Testing documented.
- [ ] Assignment traceability complete.
- [ ] Final decisions recorded.

## 8. Deployment

The assessment accepts a public deployment through Vercel, Netlify, or GitHub Pages.

Before submission:
- [ ] deployment is public;
- [ ] deployment loads without blocking errors;
- [ ] production assets resolve;
- [ ] interactions work on the deployed version;
- [ ] deployment URL is documented.

## 9. Final technical walkthrough

Be prepared to explain:
- why the architecture is divided into components;
- where state lives and why;
- how custom hooks work;
- how the selected animations work;
- how responsive behavior is implemented;
- how accessibility was considered;
- what trade-offs were made;
- what remains as future improvement.
